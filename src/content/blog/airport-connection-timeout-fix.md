## “连接超时”不等于同一种故障

机场无法连接时，用户常看到“timeout”“测速全红”“连接失败”或网页一直转圈。超时只说明某一步在规定时间内没有收到响应，可能发生在订阅下载、节点握手、DNS 解析、目标网站或客户端测试地址。

排查前先记录现象：是所有节点还是单个节点，是所有网站还是某个服务，是宽带还是移动网络，是规则模式还是全局模式。没有这些边界，反复换节点只会碰运气。

## 第一步：确认原始网络正常

完全退出代理客户端或切到直连，访问常用国内网站。若直连也失败，先处理 Wi-Fi、宽带、蜂窝数据或公共网络认证。代理无法修复已经断开的基础网络。

公共 Wi-Fi 常需要浏览器弹出认证页。先关闭代理完成登录，再开启机场。公司或学校网络可能有明确使用政策，不应尝试绕过管理限制。

## 第二步：检查套餐与订阅

登录机场用户中心，检查到期时间、剩余流量、设备限制和维护公告。然后手动更新订阅。套餐到期或流量为零时，所有机场节点可能同时不可用；旧订阅则可能仍指向已下线地址。

如果订阅也无法更新，先解决订阅域名或账户问题，参考 [机场节点不显示与更新失败排查](/blog/airport-nodes-not-showing-fix/)。如果更新正常且节点列表合理，再进入连接层。

## 第三步：选择两个不同地区节点

不要只测试一个节点，也不要一口气测速全部。选择两个不同地区的普通节点，例如一个香港、一个日本，分别测试实际网页访问。

- 单个节点失败、另一个成功：大概率是节点维护或线路故障；
- 同地区全失败、其他地区成功：可能是该地区线路异常；
- 所有地区都失败：继续检查客户端、本地网络和机场整体状态；
- 延迟测试失败但网页可开：可能是测试地址不响应，不能仅凭全红判死刑。

## 第四步：对照规则、全局与直连

在保持同一节点的前提下测试：

1. 直连模式验证本地网络；
2. 规则模式验证日常分流；
3. 全局模式短时验证节点与规则的边界。

全局正常、规则失败，重点看规则分组和 DNS；全局也失败，重点看节点、系统代理和客户端内核；浏览器正常、应用失败，重点看系统代理覆盖范围与 TUN。

## 第五步：切换网络做单变量测试

将家庭宽带切换为手机热点，保持客户端、配置和节点不变。如果热点正常而宽带超时，可能与宽带路由、DNS 或当前出口有关；两种网络都失败，则更像订阅、节点或客户端问题。

手机端也可在 Wi-Fi 与蜂窝之间比较。注意先确认应用具有蜂窝数据权限，不要在切网络同时更换协议和规则。

## 第六步：检查系统代理和客户端状态

Clash 或 v2rayN 显示已启动，不代表 Windows、Mac 浏览器已经使用代理。检查系统代理开关、活动配置、当前代理组和所选节点。若程序异常退出后系统代理残留，网页会把请求发送到无人监听的本地端口。

Windows 可在系统代理设置中确认手动代理状态；Mac 应检查菜单栏客户端是否仍运行以及当前网络服务代理；Android 与 iOS 则确认系统 VPN 标识对应正确应用。

## DNS 与时间设置

域名解析失败可能表现为网页超时，而直接连接某些 IP 仍有响应。先关闭其他安全 DNS、广告拦截和代理工具，只保留一个方案。Windows 可刷新本地 DNS 缓存，移动设备可通过断开重连网络更新状态。

设备时间严重不准确会影响 HTTPS 证书校验。开启系统自动时间并确认时区正确，不要忽略“证书尚未生效”或“证书已过期”提示。但不要因为普通节点超时就安装陌生根证书。

## TUN 和虚拟网卡故障

TUN 模式覆盖广，但会引入虚拟网卡、路由和权限问题。系统代理可用而开启 TUN 后全网超时，说明应优先检查 TUN，而不是机场节点。

处理顺序：关闭 TUN，恢复系统代理；退出其他 VPN、虚拟机网络和网络过滤工具；确认基础连接后再重新启用。不要同时安装多个服务模式或驱动。部分应用无法联网的专项流程见 [连接后部分应用无法联网](/blog/airport-connection-troubleshooting/)。

## 晚高峰、丢包与持续超时

如果白天正常、晚间固定时段超时，记录同一节点在不同时段的实际表现。延迟升高、丢包和带宽不足都可能造成页面慢，但不能凭一次 Speedtest 判断整个机场。

先切换负载较低的节点，关闭不必要的全局代理和后台大流量任务。连续多日同一时段异常，再根据 [机场晚高峰卡顿排查](/blog/airport-peak-hours-fix/) 评估线路质量。

## Clash 节点全部超时的专项检查

- 当前 Clash 配置是否为刚更新的机场订阅；
- 主代理组是否选中真实节点，而非 DIRECT 或 REJECT；
- 系统代理是否开启；
- 配置是否有解析错误并回退；
- 测试 URL 是否本身不可达；
- 是否同时运行另一个代理客户端；
- 机场公告是否显示线路维护。

导入层有错误时，可阅读 [Clash 配置错误排查](/blog/clash-config-error-fix/)；基础配置步骤见 [Clash 节点订阅教程](/blog/clash-subscription-import-guide/)。

## 小火箭节点超时的专项检查

确认顶部连接开关开启、所选为具体小火箭节点、订阅刚更新且当前规则有效。切换 Wi-Fi 与蜂窝网络，并选另一个地区节点。若显示已连接但所有网页无响应，先关闭连接确认原始网络，再排查规则。

不要为普通超时安装来源不明的重写、证书或描述文件。小火箭机场基本用法见 [Shadowrocket 订阅导入与更新教程](/blog/shadowrocket-subscription-import-guide/)。

## 建立排查记录表

| 测试项 | 节点 A | 节点 B | 结论方向 |
|---|---|---|---|
| 宽带 + 规则 | 成功/失败 | 成功/失败 | 日常路径 |
| 宽带 + 全局 | 成功/失败 | 成功/失败 | 规则影响 |
| 热点 + 规则 | 成功/失败 | 成功/失败 | 网络出口影响 |
| 订阅更新 | 成功/失败 | 不适用 | 账户与域名 |

只要记录四组结果，通常就能排除一半可能性。工单中提供这张表、发生时间和错误摘要，比只说“不能用”更容易获得有效帮助。

## 不建议的处理方式

- 公开订阅链接请陌生人代测；
- 同时修改节点、DNS、规则和 TUN；
- 关闭整机防火墙和安全软件；
- 安装来源不明的证书与修复工具；
- 节点全红就立即购买大量新套餐；
- 删除最后一份可用配置后再排查。

## 提交工单前清单

- [ ] 直连网络正常；
- [ ] 套餐有效、流量充足、订阅已更新；
- [ ] 测试了两个地区节点；
- [ ] 规则与全局完成对照；
- [ ] 宽带与热点完成对照；
- [ ] 系统代理、活动配置和代理组正确；
- [ ] 错误截图已遮住订阅和认证信息；
- [ ] 查看了机场公告。

## 常见问题

### 测速全红一定是节点不可用吗？

不一定。测试地址、客户端内核和网络限制都可能导致失败，应以实际访问和多地址测试交叉判断。

### 重启路由器有用吗？

如果问题来自本地网络、DNS 或出口状态，重连可能有帮助；如果套餐到期或配置错误，重启不会解决。

### 换协议能解决所有超时吗？

不能。首先确认机场是否官方提供相应协议与客户端支持。盲目转换节点会增加配置错误和凭证泄露风险。

### 为什么只有某个网站超时？

可能是规则、地区限制、目标服务故障或账户状态，而非整个机场。换节点地区、临时全局和查看目标服务状态可帮助判断。

## 总结

机场无法连接时，最有效的方法是按原始网络、账户订阅、两个节点、三种模式和两种网络逐层对照。把“超时”拆成具体测试结果，才能判断是机场节点、Clash 配置、小火箭规则还是本地网络。保留可用配置并保护订阅凭证，避免用高风险操作制造新的故障。
