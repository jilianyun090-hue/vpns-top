使用 AI 工具时，数据可能经过设备、浏览器或应用、机场节点、AI 中转站、模型平台和第三方插件。不同角色能看到的信息不同：机场主要参与网络传输，中转站直接接收 API 请求，模型平台处理提示词和文件，客户端与扩展则可能在本机读取页面。

隐私判断不能只问“是否加密”，而要画出完整数据路径，确定每一方的可见内容、日志、保留期限和权限。

## 一条请求经过哪些角色

直接通过机场访问官方 AI 网页时，路径通常是设备—机场—官方平台。HTTPS 正常工作时，机场一般不能读取提示词正文，但可能看到连接时间、入口 IP、流量规模和目标地址。官方平台能够处理账号、提示词、文件和输出，具体使用方式以其政策为准。

使用 AI API 中转站时，路径变成设备或应用—中转站—上游模型。中转站需要解析或转发请求，因此技术上可能接触完整正文、系统提示、文件、密钥和输出。机场与中转的区别详见[AI API 中转站和机场节点区别](/blog/ai-api-relay-vs-airport/)。

## 机场能看到什么

机场可能处理账号、订单、订阅、入口 IP、节点、连接时间、流量和工单。是否记录目标域名、保留多久、能否关联用户，取决于协议和服务商配置。所谓“无日志”没有统一定义，需要阅读具体政策。

订阅链接是访问凭证，泄露后别人可以消耗流量或使用节点。不要公开截图、上传在线转换站或发给不明客服。更完整的通用边界见[机场审计日志与隐私指南](/blog/airport-audit-privacy-guide/)。

## AI 平台能看到什么

官方平台通常需要处理账户、提示词、附件、生成结果、使用记录和安全信号。不同产品、套餐、企业版本和 API 可能有不同数据使用与保留规则。不要凭社群总结决定是否上传敏感数据，应阅读当期官方隐私与产品条款。

删除对话、关闭历史和删除账户可能有不同效果与保留周期。企业用户应使用组织批准的版本和数据处理协议。

## AI 中转站能看到什么

中转站可能记录请求正文、模型、Token、文件、响应、IP、账户和账单。即使页面写“不记录”，也要确认日志类别、保留时间、错误调试、上游传输和员工访问。

匿名、缺少政策或无法说明上游的服务不适合处理客户、医疗、法律、财务、未公开代码和个人身份数据。低价格不能抵消内容泄露的影响。

## 浏览器扩展和第三方客户端

浏览器扩展可能读取网页内容、剪贴板和访问令牌，第三方 AI 客户端可能保存对话和 API Key。只授予完成任务所需的最小权限，定期删除不用的扩展，优先使用开源可审查或信誉清晰的工具。

所谓“AI 助手”“一键登录”“共享会员”可能要求 Cookie 或账号凭证，这是高风险信号。验证码、恢复代码和 Cookie 都不应交给第三方。

## API Key 安全

API Key 应存储在服务端环境变量、密钥管理或受控 CI 系统中。不要写进浏览器 JavaScript、移动应用包、公开仓库、日志或截图。为开发、测试和生产使用不同 Key，并设置预算、速率和权限。

监控用量与异常来源，定期轮换。泄露后立即撤销并检查账单，不能只删除代码中的字符串，因为旧版本和缓存可能仍存在。

## 提示词与文件的数据分级

建立至少四级分类：公开信息、内部低敏感、机密业务、受监管或个人敏感。公开信息可在经过核验的普通工具中处理；内部信息需要明确政策；机密和受监管数据应使用企业批准的平台、合同和访问控制，或不上传外部 AI。

上传前最小化数据：删除姓名、邮箱、密钥、客户编号和不必要上下文，用占位符替换身份信息。模型只需要完成任务所需的片段，不需要整份数据库或代码仓库。

## 日志与工单也可能泄密

排查 AI 或机场故障时，人们常把完整日志发给客服。日志可能包含订阅链接、端点、请求头、模型参数、账户邮箱和文件名。提交前进行脱敏，只保留时间、错误码、去敏请求 ID 和复现步骤。

客服不会需要你的密码、验证码、Cookie、恢复代码或完整 API Key。收到此类要求应停止并核验官方渠道。

## 多设备与团队边界

个人账号不要多人共享。团队应使用平台组织、成员、角色与审计功能，分别分配权限。设备丢失或成员离开时，及时撤销会话、Key 和机场订阅。

多设备地区与客户端配置可参考[多设备 AI 工具指南](/blog/ai-tools-multi-device-guide/)，但技术可连接不代表组织允许使用。

## 第三方入口如何核验

黑喵、快AI、科技狐等导航入口都应作为第三方独立核验。本站不根据收录名称推断其模型、价格、日志或安全。查看当前隐私政策、服务条款、运营信息、模型上游、充值退款与数据删除，再决定是否使用。

首次只用非敏感内容和可承受损失的小额预算。若无法找到政策或删除方式，不要上传真实业务数据。

## 隐私检查清单

1. 画出设备、机场、中转、平台和插件的数据路径。
2. 明确每一方接触的正文、元数据、账号和账单。
3. 核对日志字段、保留期限、训练和删除政策。
4. 对提示词和文件进行数据分级与最小化。
5. API Key 使用服务端存储、独立权限和预算。
6. 账号启用双重验证，保护 Cookie 与恢复代码。
7. 日志和工单提交前彻底脱敏。
8. 高敏感业务只使用组织批准与有合同保障的方案。

## 常见问题

### 使用机场后 AI 平台看不到我吗？

不是。机场改变网络出口，平台仍能处理账号、提示词、设备与使用记录。

### HTTPS 能保护中转站前的提示词吗？

HTTPS 保护传输不被旁路读取，但中转站作为请求接收方仍能处理明文内容。

### 删除对话就没有记录了吗？

不能一概而论。应查看具体平台或中转服务的删除与保留政策。

### 企业代码可以发给低价中转吗？

不应在缺乏公司批准、合同与数据保护证明时发送机密代码。先完成供应商和合规审查。

## 结论

AI 隐私取决于整条数据链，而不是单独一个机场或模型。机场主要带来网络元数据与订阅风险，中转站和平台则可能接触完整内容。通过数据分级、最小权限、密钥管理、政策核验和脱敏，可以显著降低风险，但高敏感场景仍需要正式的企业与合规方案。
