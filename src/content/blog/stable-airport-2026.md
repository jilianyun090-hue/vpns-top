## 稳定机场的核心标准是什么？

很多人挑机场时只看价格和流量，忽略了最核心的指标：**稳定性**。

一个每小时断连3次的机场，即使每月只要5元，也会让你崩溃。而一个月付25元但全年零掉线的机场，算下来性价比反而更高。

**稳定机场的判断标准（本站使用）：**

| 指标 | 合格线 | 优秀线 |
|------|--------|--------|
| 晚高峰速度下降幅度 | < 20% | < 10% |
| 丢包率 | < 2% | < 0.5% |
| 延迟抖动 | < 20ms | < 8ms |
| 连续在线时长 | > 48小时不断流 | > 168小时稳定 |
| 敏感时期可用率 | > 90% | > 98% |

本文只收录**全部指标达标**的机场，主要为 IEPL/IPLC 专线机场。

## 为什么专线机场更稳定？

### 专线 vs 中转：本质区别

```
普通中转机场的数据路径：
你的设备 → 国内中转服务器 → [公网跨境] → 海外落地服务器

专线机场的数据路径：
你的设备 → 国内入口 → [IEPL私有专线] → 海外出口
```

**关键区别：** 专线走的是运营商的**私有物理光纤**，与公网物理隔离，不受 GFW 管控，不受晚高峰公网拥堵影响。

这就是为什么专线机场晚高峰掉速幅度只有7-9%，而普通中转机场可能掉速30-60%。

### 为什么IPLC和IEPL都叫专线？

- **IPLC（International Private Leased Circuit）**：国际私用出租线路，点对点专用电路，成本最高，稳定性最强
- **IEPL（International Ethernet Private Line）**：国际以太网专线，底层用以太网技术，扩容更灵活，成本略低

两者用户体验基本相同，都走私有物理线路不过公网。本文推荐的云图、极连云、光年梯均提供 IEPL 或 IPLC 专线。

## 如何复现稳定性测试

原文数据属于特定时间、城市与网络环境，不代表每位用户都能得到相同结果。复测时先关闭代理测本地基线，再固定设备、连接方式和测试目标；分别覆盖工作日白天、晚高峰和周末。记录延迟区间、尖峰、丢包、断流与恢复时间，不要只保存一次最快截图。

Clash 机场需要把节点问题与规则、DNS、TUN 问题分开；小火箭机场需要对比 Wi-Fi 和蜂窝网络。若只有单一网络异常，优先排查本地运营商。更系统的步骤可参考 [晚高峰排查](/blog/airport-peak-hours-fix/) 和 [连接故障指南](/blog/airport-connection-troubleshooting/)。

## FAQ

### 稳定机场可以零断线吗？

不能作绝对保证。服务器、入口、上游和客户端都会维护，关键是故障频率、冗余与恢复速度。

### 节点越多越稳定吗？

不一定。大量节点可能共享同一入口，真正冗余要看不同上游和备用路径。

### 如何降低单一机场风险？

主力服务之外保留一套低成本备用，重要工作前更新订阅并确认备用入口可用。

## 稳定性日志应记录什么

每天不必进行复杂测速，只需记录订阅能否更新、常用节点是否连接、网页与会议是否正常、是否切换过备用、故障持续多久。每周选择两个晚高峰做完整测试，包括延迟区间、丢包、持续下载和实际应用。长期日志能区分偶发维护与结构性拥塞。

评分时不要让速度掩盖断流。可以先设淘汰线：一周多次无公告中断、所有入口同时失效、流量异常扣除或工单长期无回应。通过淘汰线后，再比较价格与峰值。对 Clash 机场还要记录规则和 DNS 故障，对小火箭机场记录 Wi-Fi 与蜂窝差异，否则客户端问题会污染线路评分。

重要活动前应做预检：更新订阅、确认主力与备用节点、关闭后台同步、准备手机热点，并把直连恢复方法告知使用者。真正的稳定不是相信“永不掉线”，而是故障发生时有清楚的恢复路径。机场推荐文章也应定期更新核验日期，删除无法确认的绝对承诺。

## 不同用途的稳定标准

网页浏览允许短暂重试，视频更在意持续吞吐，会议与游戏则对抖动和丢包敏感。不能用同一测速数字覆盖所有用途。用户应先写下最重要的应用，再选择对应测试；榜单也应说明它评价的是综合稳定、游戏实时性还是视频持续性。

稳定性还包括账户与订阅。登录面板频繁失效、订阅无法更新、域名变更没有通知，即使旧节点暂时能用，也不算完整稳定。将运营、订阅、入口和出口分层评分，可以避免只看节点速度。

每季度还应清理一次旧节点和失效配置，更新备用联系方式，并确认套餐没有悄然改变倍率或设备规则。自动选择组中长期超时节点过多，会拖慢探测并干扰结果。保留少量经过验证的主力和备用，通常比收集大量名称更稳定。若工作对连续性要求高，还应准备手机热点和不同供应方的备用，而非同一面板里的多个节点。
