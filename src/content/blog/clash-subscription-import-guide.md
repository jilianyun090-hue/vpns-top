## Clash、Clash 节点和 Clash 机场分别是什么

“Clash”常被混用为客户端、配置格式和机场服务。为了避免导入时选错，先分清概念：

- **Clash 客户端**是在 Windows、Mac 或其他系统上读取配置并建立代理的工具；
- **Clash 节点**是配置文件中可供选择的代理入口；
- **Clash 机场**是能向用户提供 Clash 兼容订阅的节点服务商；
- **Clash 订阅**则是客户端定期获取节点、代理组和规则的地址。

不同维护分支的界面名称会有差别，有的把订阅称为“配置”“Profiles”或“订阅管理”。本文不绑定某个具体版本，而是按所有常见 Clash 系客户端共有的逻辑讲解，避免软件更新后按钮位置变化就无法照做。

## 导入前的准备工作

### 1. 确认客户端来源可信

优先从项目官方发布页或机场明确提供的帮助页面下载。不要安装搜索广告中的“绿色增强版”，也不要为代理功能关闭系统全部安全防护。首次打开若系统提示网络权限，只授予正常联网所需权限。

### 2. 确认套餐已经生效

登录机场用户中心检查到期时间、剩余流量和设备限制。未购买套餐、订单未支付或流量已用尽时，即使能复制订阅，也可能只得到提示节点。

### 3. 复制正确的 Clash 订阅

用户中心可能同时提供“通用订阅”“Clash”“Sing-box”“小火箭”等选项。Clash 客户端优先选择明确标注 Clash 的地址。如果只有通用订阅，应先看机场教程是否说明兼容，不要把链接交给陌生在线转换站。

关于订阅凭证保护，可先阅读 [机场订阅链接是什么与安全使用指南](/blog/airport-subscription-link-guide/)。

## Clash 节点订阅导入步骤

### 第一步：进入配置或订阅页面

打开客户端，找到“订阅”“配置”或“Profiles”。这里管理的是整份配置，不是单个节点。已有测试配置时先记录名称，不要直接全部删除。

### 第二步：新增订阅地址

选择新增订阅，将机场用户中心复制的完整 URL 粘贴到地址栏。名称建议写成服务商或用途，例如“主用 Clash 机场”。确认地址前后没有空格、中文引号或聊天软件自动附加的标点。

### 第三步：下载并激活配置

点击导入、下载或保存。成功后通常会出现更新时间、文件大小或配置名称。部分客户端还要求点选该配置才能激活；只下载而未切换到新配置，会继续使用旧节点。

### 第四步：进入代理页面选择节点

配置启用后，打开“代理”或“Proxies”。机场通常会提供“自动选择”“节点选择”“流媒体”等代理组。新手先在主选择组中手动选一个普通香港、日本或新加坡节点，不要同时调整多个策略组。

### 第五步：开启系统代理

返回主页打开“系统代理”或“System Proxy”。它会让遵循系统代理设置的浏览器和应用经过 Clash。此时先访问一个日常网站验证，不要用下载大文件作为首次测试。

## 规则、全局和直连模式怎么选

Clash 常见三种代理模式：

| 模式 | 工作方式 | 适用场景 |
|---|---|---|
| 规则模式 | 根据域名与规则决定代理或直连 | 日常使用首选 |
| 全局模式 | 大部分流量交给所选代理节点 | 临时判断分流问题 |
| 直连模式 | 不使用代理节点 | 暂停代理或基准测试 |

新手建议长期使用规则模式。全局模式适合排查“某网站在规则模式打不开”的情况，不代表速度一定更快。直连模式用于确认本地网络本身是否正常。如果规则模式异常而全局模式正常，重点检查规则分组；如果三种模式都无法访问，优先检查系统代理、节点状态和网络连接。

## 系统代理与 TUN 模式的区别

系统代理主要影响愿意读取操作系统代理设置的软件，浏览器通常支持良好；一些游戏、命令行工具或使用特殊网络栈的应用可能不读取。TUN 模式通过虚拟网络接口接管更广泛的流量，覆盖面更大，但也更容易与其他 VPN、虚拟网卡、安全软件或公司网络策略冲突。

正确顺序是先用系统代理完成基础测试，确有某些应用不走代理时再评估 TUN。开启 TUN 后若网络中断，应先关闭并恢复系统代理，不要盲目修改 DNS 和路由。相关场景可参考 [连接后部分应用无法联网排查](/blog/airport-connection-troubleshooting/)。

## 如何选择第一个 Clash 节点

节点延迟只是参考，不等于实际下载速度。选择时综合考虑：

1. **用途地区**：访问有地区限制的内容，需要匹配对应地区；
2. **距离与延迟**：日常浏览可先从香港、日本、新加坡测试；
3. **丢包和稳定性**：低延迟但频繁断流的节点并不理想；
4. **倍率**：高倍率节点会更快消耗套餐流量，可阅读 [机场节点倍率详解](/blog/node-multiplier-guide/)；
5. **机场公告**：维护中的节点即使显示也可能暂时不可用。

不要把“延迟测试失败”直接等同于节点失效。有些测试地址被拦截或不响应，但实际网页仍可访问。可以用两种测试地址或直接打开网站交叉确认。

## Clash 订阅更新的正确方式

在订阅页找到更新按钮，先更新当前配置，再回代理页确认节点列表变化。机场更换线路、续费套餐或重置订阅后都应手动更新一次。若你在原配置中直接修改规则，订阅更新可能覆盖这些改动；长期自定义应使用客户端提供的覆写、合并或本地规则功能，并先备份。

自动更新无需设置得非常频繁。节点没有变化时，重复拉取不会改善速度。更新失败时保留当前可用配置，避免一边排查一边删除最后一份能够工作的文件。

## 导入失败的分层排查

### 提示 URL 或网络错误

重新从用户中心复制完整链接，检查套餐状态。用手机热点和宽带交叉测试，以区分本地网络与订阅域名问题。不要把链接公开发出求助。

### 提示 YAML 或配置格式错误

这通常表示服务端返回的不是 Clash 配置，或内容在转换过程中损坏。确认选择了 Clash 专用订阅；若机场有备用订阅域名，按官方说明替换。更深入的语法排查见 [Clash 配置错误与订阅导入失败排查](/blog/clash-config-error-fix/)。

### 下载成功但代理页为空

先确认新配置已被选中，再清理代理页的关键词筛选。若只显示套餐到期信息，回用户中心检查订单。可继续参考 [机场节点不显示排查指南](/blog/airport-nodes-not-showing-fix/)。

### 节点有延迟但网页打不开

检查系统代理是否开启，模式是否误选为直连，主代理组是否选中了真实节点而非“REJECT”。然后换一个地区节点测试。如果只有单个网站异常，再判断规则和 DNS，而不是立刻重装客户端。

### 关闭 Clash 后仍无法联网

可能是程序异常退出后系统代理没有恢复。重新打开客户端关闭系统代理，或在系统网络设置中关闭手动代理。确认没有其他代理软件同时接管同一端口。

## Windows 与 Mac 使用差异

Windows 上需要留意系统代理残留、防火墙提示、虚拟网卡和多个代理客户端抢占端口。Mac 上应关注系统网络扩展权限、不同网络服务的代理设置，以及休眠唤醒后的连接状态。两端通用原则都是：同一时间只保留一个主代理客户端，先验证系统代理，再按需开启 TUN。

针对系统选择和更完整检查，可阅读 [Windows 机场客户端与 Clash 节点配置](/blog/windows-airport-client-guide/) 与 [Mac 机场客户端选择与配置](/blog/mac-airport-client-guide/)。

## 安全与隐私清单

- 不公开完整机场订阅、配置文件和包含认证参数的日志；
- 不把公司、学校或他人的设备用于未经授权的代理配置；
- 不安装来历不明的内核、证书或所谓加速补丁；
- 退出或卸载前先关闭系统代理与 TUN；
- 定期删除已到期订阅，避免选错旧节点；
- 遵守所在地法律法规及所访问服务的使用条款。

## 常见问题

### Clash 机场能直接在浏览器里登录使用吗？

机场网站用于注册、购买和复制订阅；真正建立代理的是本地 Clash 客户端。只登录网站不会自动让网络走节点。

### 一份订阅可以导入多个 Clash 客户端吗？

技术上通常可以，但要遵守机场的设备数和同时在线限制。多个设备同时使用还会共同消耗套餐流量。

### 自动选择一定比手动节点快吗？

自动选择依据取决于配置，可能只比较延迟，未必反映晚高峰稳定性。重要任务前可手动测试两三个节点。

### Clash 节点越多越好吗？

数量不是质量。少量维护及时、地区明确的节点，比大量重复、失效或命名混乱的节点更容易使用和排查。

## 完成后的核验清单

- [ ] 订阅来自官方用户中心且格式匹配；
- [ ] 下载后的配置已激活，不是仍在使用旧文件；
- [ ] 主代理组已选真实机场节点；
- [ ] 日常使用规则模式，系统代理已正常开启；
- [ ] 至少用两个节点完成网页访问测试；
- [ ] 退出客户端后系统代理能正常恢复；
- [ ] 完整订阅链接没有出现在截图或公开日志中。

## 总结

Clash 节点订阅导入的关键并不是找到某个固定按钮，而是理解“获取正确格式—下载配置—激活配置—选择节点—开启代理—验证规则”的完整链路。按层次操作，Clash 机场出现问题时就能判断故障位于订阅、配置、代理组、系统代理还是节点线路，避免反复重装和随意改动造成新的错误。
