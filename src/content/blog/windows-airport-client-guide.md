## Windows 机场客户端如何选

Windows 可选的机场客户端很多，常见路线是 Clash 兼容客户端、v2rayN 和其他支持通用订阅的工具。选择依据不是“功能越多越好”，而是机场格式兼容、项目来源可信、界面容易回退，以及是否真的需要 TUN、脚本或复杂规则。

如果机场主要提供 Clash 订阅，选择维护正常的 Clash 兼容客户端更省事；如果服务商提供 v2rayN 或通用订阅，可参考 [v2rayN 机场节点配置教程](/blog/v2rayn-airport-client-guide/)。不要把陌生整合包当作官方客户端。

## 安装前建立干净基线

先关闭现有代理软件，在 Windows 设置中确认手动代理处于关闭状态，并验证浏览器能正常访问日常网站。记录当前网络是宽带、公司网络还是手机热点。这个基线很重要：如果安装前网络本身就异常，后续无法判断问题来源。

同时登录机场用户中心确认套餐、流量和公告，复制与客户端匹配的订阅。完整链接不要贴进公开日志，安全细节见 [机场订阅链接安全使用指南](/blog/airport-subscription-link-guide/)。

## Windows 导入 Clash 节点

1. 打开配置或订阅页面；
2. 从 URL 新增订阅，填写机场名称；
3. 粘贴完整 Clash 订阅并下载；
4. 将下载到的配置设为当前配置；
5. 进入代理组选择普通机场节点；
6. 开启系统代理，使用规则模式测试。

导入成功与连接成功是两回事。配置出现在列表中只说明文件下载完成，还需要激活配置、选择节点并打开代理。详见 [Clash 节点订阅完整教程](/blog/clash-subscription-import-guide/)。

## Windows 系统代理的工作方式

开启系统代理后，客户端通常让 Windows 将 HTTP/HTTPS 请求发送到本机监听端口。浏览器和遵循系统设置的应用会使用该端口。如果客户端异常退出，而系统代理仍指向本地端口，就会出现“关掉软件反而全网断开”。

恢复方法是重新打开客户端并正常关闭系统代理，或进入 Windows 网络与 Internet 的代理设置关闭手动代理。不要先重置整个网络或删除网卡；先修复最小范围的代理状态。

## 什么时候需要 TUN

部分游戏、命令行程序和独立网络应用不读取系统代理。TUN 通过虚拟网卡覆盖更广泛的流量，适合明确需要的场景，但可能与其他 VPN、虚拟机、容器网络、杀毒软件和单位管控发生冲突。

推荐顺序：

1. 系统代理下确认浏览器和节点正常；
2. 检查目标应用自身代理设置；
3. 关闭其他 VPN 与虚拟网络工具；
4. 再启用 TUN 并单独测试目标应用；
5. 异常时先关闭 TUN 回到已验证的系统代理。

## 规则模式与全局模式

日常使用规则模式，让国内地址直连、需要的请求走 Clash 节点。全局模式适合短时判断分流规则是否有问题。直连模式用于确认 Windows 原始网络。

三组对照很有用：直连失败说明先修本地网络；直连正常、全局失败说明看节点或代理；全局正常、规则失败说明看规则分组。按此顺序比随意改 DNS 更容易定位。

## 防火墙、端口和多个客户端冲突

首次启动时 Windows 可能询问防火墙网络访问。核对程序来源和路径后按实际网络类型授权。不要直接关闭整个防火墙。

两个代理客户端同时运行可能争用本地端口，或轮流修改系统代理。常见表现包括启动失败、端口占用、界面显示已连接但流量进入另一个程序。处理时完整退出其他客户端，检查托盘区是否仍有图标，再重启当前工具。

如果电脑同时运行开发服务器、虚拟机或容器，修改本地端口前先记录原值，避免与开发环境冲突。只调整发生冲突的端口，不要随机更改所有监听项。

## 常见故障排查

### 机场订阅下载失败

重新复制地址，检查账户和套餐。用手机热点与宽带交叉测试，按官方公告使用备用域名。不要向陌生人发送完整订阅代测。

### Clash 配置提示错误

确认选择了 Clash 专用订阅，不是网页地址或其他客户端格式。保留错误摘要，可参照 [Clash 配置错误排查](/blog/clash-config-error-fix/) 逐层检查。

### 节点列表为空

确认新配置已激活、代理页无筛选、套餐有效。进一步见 [机场节点不显示与更新失败](/blog/airport-nodes-not-showing-fix/)。

### 浏览器能用，桌面程序不能用

应用可能不读取系统代理。检查其代理设置，用全局模式和 TUN 作对照。相关原因见 [连接后部分应用无法联网](/blog/airport-connection-troubleshooting/)。

### 所有节点连接超时

先确认直连网络，更新订阅，换两个地区节点，再换热点。查看机场公告和套餐状态。若只在某个网络失败，重点检查该网络而非重装客户端。

### DNS 解析异常

表现为域名打不开但部分 IP 请求可能有响应。先退出其他代理和安全 DNS 工具，恢复基础设置，刷新系统 DNS 缓存后重试。不要同时启用多个 DNS 接管方案。

### 重启电脑后客户端失效

检查客户端是否正常启动、订阅是否仍为活动配置、系统代理是否被其他软件覆盖。不要假设开机自启一定成功，先手动启动验证。

## 选择 Windows 机场节点

首次选择近距离普通节点，实际访问成功后再按地区需求切换。延迟低并不保证持续带宽，高倍率会影响套餐消耗。阅读 [机场节点倍率详解](/blog/node-multiplier-guide/) 可理解 1 倍率和高倍率的差别。

晚高峰应记录同节点不同时段表现，避免只凭白天测速。若晚上卡顿，可按 [机场晚高峰解决方法](/blog/airport-peak-hours-fix/) 先换节点和分流，再判断线路质量。

## Windows 安全清单

- [ ] 客户端来自官方或可信发布渠道；
- [ ] 不安装要求永久关闭防护的修改版；
- [ ] 订阅格式匹配且未公开泄露；
- [ ] 同一时间只让一个主客户端修改系统代理；
- [ ] 开启 TUN 前已验证系统代理；
- [ ] 退出后检查 Windows 代理是否恢复；
- [ ] 不在未经许可的单位设备上绕过网络策略。

## 常见问答

### Windows 用 Clash 还是 v2rayN？

先看机场支持格式和你的使用需求。需要完整 Clash 规则配置时选兼容客户端；机场提供通用订阅且偏好简单节点管理时可考虑 v2rayN。

### 系统代理和 TUN 可以同时开吗？

部分客户端可以协调两者，但新手不应把“双开”当作更快。先单独验证系统代理，有明确需求再按客户端说明启用 TUN。

### Clash 节点测速全部超时就是机场跑路吗？

不能直接判断。测试地址、当前网络、订阅过期和客户端内核都可能导致全红，应通过实际访问、换网络和查看公告交叉验证。

### 卸载客户端后为什么浏览器不能联网？

可能是系统代理残留。进入 Windows 代理设置关闭手动代理，再检查浏览器扩展和其他代理工具。

## 总结

Windows 机场配置的重点是保持单一、可回退的网络路径：先建立直连基线，再导入匹配订阅，激活 Clash 节点，开启系统代理，最后才按需使用 TUN。通过直连、规则、全局和不同网络的对照，可以定位绝大多数问题，同时避免关闭安全功能或反复重装带来的额外风险。
