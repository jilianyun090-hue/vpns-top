## Mac 机场客户端选择先看兼容性

Mac 用户常在 Clash 兼容客户端、Sing-box 类客户端和其他通用代理工具之间选择。没有一个软件适合所有机场，因为服务商支持的协议和订阅格式不同。先查看机场帮助中心提供的 macOS 方案，再考虑界面、规则、TUN 与多配置管理。

客户端只是执行工具，机场节点来自你购买的订阅。搜索到“免费 Mac 梯子”并不等于可靠机场，来源不明的配置可能失效、记录流量或附带高风险脚本。

## 下载和安装前检查

1. 确认 Mac 芯片架构与系统要求，选择项目官方提供的安装包；
2. 不为安装未知应用长期关闭系统安全机制；
3. 检查机场套餐、剩余流量与公告；
4. 复制与客户端匹配的 Clash 或通用订阅；
5. 退出其他 VPN、代理客户端和会修改系统代理的工具。

如果不了解订阅安全，先看 [机场订阅链接安全使用指南](/blog/airport-subscription-link-guide/)。

## Mac 导入 Clash 节点的通用流程

打开客户端的配置或订阅页面，从 URL 新增订阅。粘贴完整地址，为配置填写清晰名称，然后执行下载。下载成功后必须将该配置设为活动配置，再进入代理组选择机场节点。

回到主界面开启系统代理。macOS 可能要求授权修改网络设置或安装辅助服务；只在应用来源可信且功能确有需要时授权。首次测试先使用普通系统代理，不急于开启 TUN。

推荐验证顺序：

1. 关闭代理时确认 Safari 或其他浏览器能访问日常网站；
2. 开启系统代理，选择一个近距离节点；
3. 使用规则模式访问两个 HTTPS 网站；
4. 换另一个地区节点重复测试；
5. 最后再测试需要地区匹配的服务。

更具体的 Clash 逻辑见 [Clash 机场订阅导入完整教程](/blog/clash-subscription-import-guide/)。

## 系统代理与 TUN 怎么选

macOS 系统代理适合浏览器和遵循系统设置的应用，配置简单、冲突较少。TUN 或增强模式通过网络扩展覆盖更多应用，但需要额外权限，也可能与企业安全软件、其他 VPN、虚拟机网络和开发工具冲突。

建议先用系统代理。如果只有终端、游戏或某个应用不走代理，再检查应用自身代理支持，然后评估 TUN。开启 TUN 后若全机断网，第一步是关闭 TUN 并恢复基础系统代理，而不是继续叠加 DNS 或路由修改。

## Mac 多网络环境注意事项

MacBook 经常在家庭 Wi-Fi、公司网络、手机热点和公共网络间切换。系统代理可能针对不同网络服务保存状态，公共 Wi-Fi 还可能要求先完成网页认证。

切换网络后建议：

- 暂停机场客户端，确认新网络本身已联网；
- 公共 Wi-Fi 先完成登录认证，再开启代理；
- 更新节点或重新连接当前配置；
- 若热点可用而公司网络不可用，尊重单位网络政策，不尝试绕过限制；
- 记录是哪一个网络服务出现异常，不要把问题笼统归为 Mac 客户端故障。

## 休眠唤醒后无法连接

休眠会中断旧网络会话，唤醒时 Wi-Fi 地址、DNS 或路由状态可能变化。遇到节点显示连接但网页无响应，可按以下顺序操作：

1. 关闭系统代理或断开客户端；
2. 确认 Wi-Fi 已重新获取网络并可直连；
3. 重新连接原节点；
4. 不行再切换另一个节点；
5. 仍异常时退出并重新打开客户端。

不要每次休眠后都删除配置。订阅本身通常没有损坏，重新建立网络会话即可。

## 终端与浏览器结果不同

浏览器通常读取系统代理，终端命令是否读取取决于工具和环境变量。因此 Safari 可访问而命令行失败，并不能证明机场节点异常。检查命令行工具是否需要显式代理变量，或是否必须在 TUN 下工作。

配置开发环境时，不要把含认证信息的代理地址写进公开仓库。移除客户端后也要清理自己添加的 shell 环境变量。只为临时测试添加设置，并记录如何回退。

## 常见故障排查

### 订阅无法下载

重新从用户中心复制，检查套餐和链接完整性。用热点与当前 Wi-Fi 交叉测试。机场有备用订阅域名时按官方公告使用。

### 下载后没有节点

确认配置已激活、筛选已清除、格式与客户端兼容。详细参考 [机场节点不显示排查](/blog/airport-nodes-not-showing-fix/)。

### 浏览器完全断网

关闭系统代理验证原始网络；确认客户端内核正在运行，系统代理端口与客户端监听一致。若程序已退出而代理仍开启，macOS 会继续把流量交给无人监听的本地端口。

### 只有某些应用不通

检查应用是否忽略系统代理、是否需要 UDP，或是否被规则判定为直连。临时全局模式可用于对照，完成后恢复规则模式。更多流程见 [部分应用无法联网排查](/blog/airport-connection-troubleshooting/)。

### TUN 启动失败

检查网络扩展或辅助服务权限，退出其他 VPN 与网络过滤工具后重试。不要反复安装多个来源不同的服务组件。

### 晚上速度明显变慢

使用相同节点在不同时段记录延迟、丢包与实际播放表现，再换不同地区节点。参考 [机场晚高峰卡顿解决方法](/blog/airport-peak-hours-fix/)，避免只凭一次测速下结论。

## 选择节点与控制流量

日常先从近距离普通节点开始，有地区限制时再选择对应地区。延迟、带宽和稳定性是不同指标。高倍率节点会按更高比例扣除套餐流量，Mac 系统更新、云同步和备份任务若走全局代理，可能快速消耗配额。

使用规则模式可让不需要代理的流量直连。执行大文件同步前检查当前节点和倍率，并确认机场套餐是否允许相应使用方式。

## 安全核验清单

- [ ] 安装包来自官方或可信发布渠道；
- [ ] 订阅格式与客户端匹配且未公开泄露；
- [ ] 活动配置和主代理组已正确选择；
- [ ] 先验证系统代理，再按需启用 TUN；
- [ ] 切换网络后先确认原始网络可用；
- [ ] 终端代理设置未写入公开项目；
- [ ] 退出客户端后系统代理能够恢复。

## 常见问答

### Mac 必须使用 Clash 机场吗？

不必须。关键是客户端与机场协议、订阅格式匹配。Clash 机场只是常见选择之一。

### 同一订阅能在 Mac 和 Windows 使用吗？

通常可以，但要遵守套餐设备限制，并为各自客户端选择兼容格式。两台设备会共享流量。

### 为什么 Safari 可用但 App Store 不稳定？

不同应用对系统代理和网络服务的使用方式不同，规则也可能将相关域名分到不同策略。先用规则与全局对照，不要直接修改系统证书。

### 关闭窗口等于退出客户端吗？

许多 Mac 应用关闭窗口后仍在菜单栏运行。需要停用时，应先关闭系统代理或 TUN，再从菜单中真正退出。

## 总结

Mac 配置机场的重点是选择兼容且可信的客户端，按顺序完成订阅、活动配置、节点与系统代理，并谨慎处理 TUN 权限。多网络和休眠环境下，先恢复基础联网再重连；通过单变量测试区分系统代理、规则和线路问题，能避免不必要的重装与安全风险。
